## Why

当前用户密码体系已经改成“密码必填校验 + 首次设置密码 + 通过客服工单重置密码”的模型，但密码重置工单最初仍是内存存储。服务重启后工单会丢失，这不满足资产管理场景下对后台处理记录和审计留痕的基本要求。

另外，管理端已经复用了用户激活工单的队列页来处理密码重置工单，因此工单数据源也需要与现有管理端工作流一致，改成数据库持久化。

## What Changes

- 新增用户密码重置工单能力，支持用户提交忘记密码工单，客服审核后生成临时密码，并强制用户下次登录后立即重置正式密码。
- 将密码重置工单从内存存储改为数据库持久化，避免服务重启后工单丢失。
- 在管理端用户页复用现有工单队列展示密码重置工单，并支持 `待处理`、`处理中`、`已办结`、`已归档` 队列操作。
- 保持临时密码登录后的强制改密链路，确保临时密码只作为一次性过渡凭证使用。

## Capabilities

### Modified Capabilities

- `admin-management-console`: 管理端用户页必须展示并处理密码重置工单队列。
- `account-activation-binding`: 管理端工单管理模式扩展到密码重置类工单，复用相同的队列生命周期。
- `public-account-authentication`: 用户登录必须校验密码；未设置密码和临时密码用户必须分别进入首次设置密码或强制重置密码流程。

## Impact

- Database: 新增密码重置工单表与迁移。
- Public auth: 登录、首次设置密码、忘记密码申请、强制重置密码链路调整。
- Admin UI/API: 管理端新增密码重置工单读取与处理动作。
- Security: 临时密码审批后落库，用户登录后必须立即更换为正式密码。
