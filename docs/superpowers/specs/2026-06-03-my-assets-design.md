# 我的资料独立页面设计

日期：2026-06-03

## 背景

当前仓库已经具备“用户手动将模型生成的图片/视频保存到云端”的基础能力：

- `POST /api/user/media-assets` 可将指定运行产物保存到云端。
- `GET /api/user/media-assets` 可列出当前用户已保存资产。
- `GET /api/user/media-assets/[assetId]` 与 `DELETE /api/user/media-assets/[assetId]` 已具备单资产读取与软删除能力。
- `/user-center` 中已有轻量 `UserMediaModule`，但它只是简表展示，不足以承担完整资料库体验。

本次变更目标是在用户端新增独立一级页面“我的资料”，让用户集中管理已手动保存到云端的图片/视频资料，并通过顶部导航在登录态进入。

## 范围

首版只覆盖以下范围：

- 独立一级页面展示“我的资料”。
- 只管理用户主动点击“保存到云端”的图片/视频。
- 支持列表查看、搜索、类型筛选、时间排序、预览、删除、下载、继续对话。
- 顶部全局导航在登录态显示“我的资料”入口。

明确不做：

- 不自动将所有生成结果入库。
- 不管理聊天文本。
- 不管理用户上传给模型的参考资料。
- 不在首版引入新的通用“多模态资料中心”抽象。

## 任务分类

这是一个 Large 任务，因为它包含：

- 新用户功能与新的一级用户页面。
- 用户可见导航结构变化。
- 跨页面、API、服务端下载能力与现有持久化边界协作。

## 现状与可复用基础

### 已有边界

- 页面与 UI：
  - `src/app/user-center/page.tsx`
  - `src/features/public/user-media-module.tsx`
  - `src/features/public/home-page.tsx`
- 用户媒体 API：
  - `src/app/api/user/media-assets/route.ts`
  - `src/app/api/user/media-assets/[assetId]/route.ts`
- 资料保存服务：
  - `src/server/media/save-generated-media.ts`
- 资料仓储：
  - `src/server/repositories/generated-media-assets.ts`

### 当前数据语义

- 资料真相表为 `generated_media_assets`。
- 只有用户手动保存时才创建资产记录。
- 列表仅返回 `status = ready` 且未软删除的数据。
- 删除为软删除，不直接抹除原始生成记录。

## 状态所有权

| 状态 | Owner | 写入口 | 真相来源 |
| --- | --- | --- | --- |
| 已保存资料集合 | `generated_media_assets` 仓储 | `POST /api/user/media-assets`、`DELETE /api/user/media-assets/[assetId]` | 数据库 / 开发环境内存仓储 |
| 资料保存资格与去重 | `save-generated-media` 服务 | 用户在生成结果处点击保存 | 运行详情 + 仓储 |
| 页面搜索词/筛选/排序/预览弹层 | `my-assets` 页面本地状态 | 页面交互 | 客户端派生状态 |
| 导航入口显示 | 当前登录态 | `useAuth()` | 会话状态 |

## 不变量

1. 只有当前登录且激活的用户可以查看、预览、下载、删除自己的资料。
2. “我的资料”只显示已成功保存到云端且未删除的图片/视频。
3. 资料入库只来自用户手动保存，页面本身不触发自动入库。
4. 删除资料只影响资料库可见性，不回滚或删除原始生成运行。
5. 前端不直接信任对象存储路径进行授权，下载与预览应通过服务端受控能力暴露。

## 方案选择

### 方案 1：独立页面 + 复用现有媒体资产 API + 新增受控下载能力

做法：

- 新增独立页面 `/my-assets`。
- 复用现有媒体资产列表/详情/删除接口。
- 导航登录态新增“我的资料”入口。
- 搜索、筛选、排序先在前端完成。
- 新增服务端受控预览/下载入口。

优点：

- 与用户希望的一级页面一致。
- 最大化复用当前保存链路与仓储。
- 风险集中，不需要为未来多模态资料提前泛化。
- 安全边界清晰，预览/下载不直接暴露原始存储对象信息。

缺点：

- 首版的搜索与筛选是前端内存操作，不适合超大资料量。

### 方案 2：继续扩展 `/user-center` 再补独立页面

优点：

- 可以复用当前轻量模块。

缺点：

- 与已确认的“独立一级页面”方向冲突。
- 容易造成用户中心与独立页面双维护。

### 方案 3：直接抽象通用资料中心

优点：

- 为未来文本、音频、上传文件提供统一模型。

缺点：

- 明显超出当前首版范围。
- 会把简单媒体库问题升级成抽象工程。

### 推荐

采用方案 1。

## 最终设计

### 信息架构

- 新增一级路由：`/my-assets`
- 页面中文标题：`我的资料`
- 顶部全局导航：
  - 桌面端登录态展示“我的资料”
  - 移动端折叠菜单登录态展示“我的资料”
  - 未登录态不显示入口
- `/user-center` 中现有媒体模块降级为轻摘要或跳转入口，不再承担完整资料库功能

### 页面结构

页面由三部分组成：

1. 顶部工具栏
2. 资料卡片网格
3. 预览层

#### 顶部工具栏

包含：

- 搜索框：按标题搜索
- 类型筛选：全部 / 图片 / 视频
- 时间排序：最新优先 / 最早优先

首版不做复杂筛选器。

#### 资料网格

- 使用卡片网格，不使用后台表格。
- 每张卡片展示：
  - 缩略图或视频封面占位
  - 标题
  - 类型
  - 文件大小
  - 保存时间
- 每张卡片提供动作：
  - 预览
  - 继续对话
  - 下载
  - 删除

#### 预览层

- 图片：大图预览
- 视频：弹层内播放
- 预览层内仍保留“下载”和“继续对话”快捷动作

### 页面行为

- 默认按 `savedAt` 倒序显示。
- 搜索、类型筛选、时间排序全部基于当前列表结果派生。
- “继续对话”跳转保持现有约定：`/chat?assetId=<id>`。
- 删除使用二次确认。
- 删除成功后从当前列表即时移除。
- 空状态提供去 `AI生图` 与 `AI视频` 的入口。
- 页面需要完整处理：
  - 加载中
  - 加载失败
  - 搜索无结果
  - 空资料
  - 删除失败

## API 设计

### 继续复用

- `GET /api/user/media-assets`
- `GET /api/user/media-assets/[assetId]`
- `DELETE /api/user/media-assets/[assetId]`

首版不改动这三个接口的基础职责。

### 新增能力

新增一个受鉴权的预览/下载入口，建议形态之一：

- `GET /api/user/media-assets/[assetId]/access`

返回受控访问结果，例如：

- 临时签名 URL
- 内容类型
- 访问模式（`preview` / `download` 可按查询参数区分）

推荐原因：

- 避免前端直接暴露对象存储位置作为授权依据。
- 后续若 COS 签名策略变化，前端无需重构。
- 可在服务端统一校验用户归属与资产状态。

如果实现层面更适合拆分为两个路由：

- `GET /api/user/media-assets/[assetId]/preview`
- `GET /api/user/media-assets/[assetId]/download`

也可以接受，但语义应保持“服务端校验后签发受控访问能力”。

## 服务端设计

### 读取与删除

继续由 `generated-media-assets` 仓储负责：

- 列表读取用户自己的可见资产
- 单资产读取用户自己的可见资产
- 软删除用户自己的可见资产

### 预览/下载访问控制

新增服务端访问能力时应执行：

1. 校验当前用户已登录且激活
2. 根据 `assetId + userId` 读取资产
3. 仅允许 `status = ready` 且未删除资产访问
4. 基于资产对象键向存储层请求临时访问 URL 或流式代理
5. 将受控结果返回页面

### 对象存储边界

前端不得自行拼接：

- `bucket`
- `region`
- `objectKey`

这些字段是服务端与存储集成的内部细节，不是前端授权依据。

## 前端落点

建议新增：

- `src/app/my-assets/page.tsx`
- `src/features/public/my-assets-page.tsx`
- `src/features/public/my-assets-grid.tsx`
- `src/features/public/my-assets-preview-dialog.tsx`

允许根据实现复杂度合并为更少文件，但原则是：

- route 文件只做边界装配
- 页面交互逻辑进入 feature 模块

还需修改：

- `src/features/public/home-page.tsx`
  - 登录态导航增加“我的资料”入口
  - 移动端菜单同步增加
- `src/app/user-center/page.tsx`
  - 现有完整媒体模块降级为轻摘要或跳转入口

## 错误与恢复

- 列表加载失败：展示错误提示与重试
- 删除失败：保留当前卡片并展示错误
- 预览地址获取失败：预览层内展示失败提示
- 下载地址获取失败：不跳空白页，保留页面内错误反馈
- 资料被删除或不存在：详情/访问接口返回 404，页面应提示资料不存在并触发列表刷新

## 安全语义

- 导航隐藏只用于体验，不作为权限控制。
- 页面路由和 API 都必须依赖现有登录/激活校验。
- 所有单资产操作都必须以 `assetId + currentUserId` 作为查询条件。
- 未登录用户即便手动访问 `/my-assets` 或相关 API，也必须被拒绝。

## 验证策略

最低验证层建议如下：

1. 针对新增访问路由和已有列表/删除行为补充路由测试
2. 针对前端搜索/筛选/排序派生逻辑补充单测或组件级测试
3. 运行 `pnpm validate`
4. 运行 `pnpm build`
5. 启动本地页面做浏览器验证，至少覆盖：
   - 登录态导航出现“我的资料”
   - 未登录态导航不出现入口
   - 空状态
   - 列表展示
   - 搜索/筛选/排序
   - 删除
   - 预览
   - 下载触发

如果受本地登录态、存储签名或浏览器环境限制，需明确记录 blocker。

## 分阶段实现建议

建议拆为以下实现顺序：

1. 新建 `/my-assets` 页面与基础页面骨架
2. 接入现有列表 API 与前端搜索/筛选/排序
3. 完成卡片网格、空状态、错误态、删除
4. 新增服务端受控预览/下载能力
5. 接入预览弹层与下载动作
6. 更新顶导航与移动端菜单
7. 将 `/user-center` 媒体模块降级为摘要/跳转

## 本地设计结论

本次首版不扩展数据模型，不引入自动保存，不提前泛化为通用资料中心。核心是把已经存在的“保存到云端”能力升级为一个独立、可管理、受鉴权保护的用户资料库页面，并在登录态导航中提供稳定入口。
